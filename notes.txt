# Project Summary

**Name:** harness-openrouter

**Description:**
A small, extensible coding-agent harness built with TypeScript, Bun, and the OpenRouter Chat Completions API. It implements an iterative agent loop that sends prompts to an OpenRouter model, exposes local tools via function calling, executes requested tools, and returns results to the model until a final response is produced.

**Architecture:**
Follows a lightweight Clean Architecture pattern with clear separation of concerns:

- **src/domain/** – Core entities (messages, tool calls), repository interfaces, and services (agent orchestration, tool registry).
- **src/infrastructure/** – Concrete implementations: OpenRouter LLM adapter, local tool implementations (read_dir, read_file, write_file, execute_bash), and environment configuration.
- **src/index.ts** – Composition root and CLI entry point.

**Built-in Tools:**
- `read_dir` – List directory contents.
- `read_file` – Read UTF-8 files (truncated at ~200 KB).
- `write_file` – Write or append text files (creates parent directories).
- `execute_bash` – Run Bash commands with a configurable timeout.

**Configuration (via .env):**
- `OPENROUTER_API_KEY` (required)
- `OPENROUTER_MODEL` (default: deepseek/deepseek-chat)
- `AGENT_SYSTEM_PROMPT` (optional override)
- `MAX_ITERATIONS` (default: 12)
- `OPENROUTER_BASE_URL` (default: https://openrouter.ai/api/v1)

**How It Works:**
The agent loop sends conversation messages and tool definitions to OpenRouter. If the model responds with tool call requests, the harness executes the corresponding local tool and feeds the result back into the conversation. This repeats until the model produces a final text response or the iteration limit is reached.

**Dependencies:** Bun, TypeScript, @types/bun.

**Usage:**
```bash
bun start "Your prompt here"
```

**Limitations:**
- Single-run CLI process (no persisted conversation history).
- No sandbox or approval step for tool execution.
- No explicit HTTP timeouts or retry policies.
- No automated tests yet.
